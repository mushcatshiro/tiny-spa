Welcome to the home page of Tiny-SPA.

Why Tiny-SPA?

There are a few main motivation of creating Tiny-SPA, including to learn javascript/frontend framework design, to have something lightweight but battery included to build internal toolings, and most importantly, a gear switch from server/application code.

How Tiny-SPA Works?

Tiny-SPA at its core is a router that register routes and handles route change by creating the new page's component, attaching it to the preferred app's main div. By default, errors are rendered to the UI, which can be an undesired behavior that forces errors to be handled better at component level.

Styles is offerred at page and component level. A page level style expects a *.css file that matches the *.html filename. The style might not be applied onto the page depending on the *.css file transfer speed, and can result in a untyled page until it is fully loaded. Page level style will be removed upon route changes. Component level style is optional. Most if not all out-of-box components have a default style, that can be overwritten. It creates a style scoped to the component itself and is removed upon the component is unmouned.

In terms of lifecycle, there is only three: construction, onMount and onUnmount. onChange is missing and is preferred to be explicitly writen with `HTMLElement.addEventListener` or equivalent. More on lifecycle management is documented here.

Below is a simple guide on using the framework.

Step 1: Hello World

Here's a basic project structure and the file contents.

  project-name
  |_index.html
  |_main.js
  
  // main.js
  import TinySpa from 'tiny-spa/router.js';
  const app = new TinySpa();

Step 2: Controller and Components

A controller is equivalent to a page, which can consist of many components.

  project-name
  |_index.html
  |_main.js
  |_pages
    |_hello.html
    |_hello.js

All controllers should extend from BaseController to ensure they can be registered to the router.

  // hello.js
  import { BaseController  } from 'tiny-spa/baseController.js'

  export class HelloController extends BaseController {
    constructor(appId) { super(appId) }
    async onMount {
      const targetElement = document.getElementById(this.appId);
      targetElement.innerHTML = `This page failed during route registering.`
    }
  }

Controller should be concerned about the layout and placement of each component, Component provides the rest.

Take note that the id should be unique and not colliding with the main app's id to prevent unhandled errors.

Step 3: Registering a route

  // main.js
  import HelloController from './helloController.js'
  // ...
  app.registerRoute('/', './hello.html', helloController);

A route should consist of at least a *.html file and a *.js file.

Step 4: Build and Deploy

Vite is the preferred build tool for Tiny-SPA and the only external dependency required. Simply run the following command

  vite build && vite preview

The --minify flag can be used for debugging. The files will be found in the dist directory by default. To deploy the SPA, with e.g. Nginx, copy the files in dist directory
